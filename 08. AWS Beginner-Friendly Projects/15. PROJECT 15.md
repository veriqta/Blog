# Project 15: Create an S3 File Processing Workflow

In this project, you will stop invoking Lambda manually.

Instead, an action in Amazon S3 will automatically start the workflow.

The trigger will be:

```text
A FILE IS UPLOADED
```

The architecture is:

```text
USER / APPLICATION
        |
        | Upload file
        v
+---------------------------+
| AMAZON S3                 |
|                           |
| Project 15 Bucket         |
|                           |
| uploads/file.txt          |
+-------------+-------------+
              |
              | ObjectCreated event
              v
+---------------------------+
| AWS LAMBDA                |
|                           |
| Python 3.14               |
|                           |
| Read event information    |
| Inspect object metadata   |
| Log processing result     |
+-------------+-------------+
              |
              v
+---------------------------+
| AMAZON CLOUDWATCH LOGS    |
|                           |
| File name                 |
| Bucket                    |
| Size                      |
| Content type              |
| Event type                |
| ETag                      |
+---------------------------+
```

Amazon S3 can publish event notifications when objects are created or deleted, and Lambda is one of the supported destinations.

The workflow will:

```text
1. Upload a file.

2. S3 creates an ObjectCreated event.

3. S3 invokes Lambda.

4. Lambda reads the S3 event.

5. Lambda extracts the bucket and object key.

6. Lambda requests object metadata.

7. Lambda writes processing information to logs.

8. CloudWatch stores the execution logs.
```

# Part 1: Understand Event-Driven Processing

Without an event trigger, you might do this:

```text
Upload file
    |
    v
Manually invoke Lambda
```

That does not scale well.

With event-driven processing:

```text
Upload file
    |
    v
S3 detects event
    |
    v
Lambda automatically runs
```

S3 Event Notifications exist specifically so applications can react when selected events occur in a bucket.

The important idea is:

```text
EVENT
   |
   v
TRIGGER
   |
   v
PROCESSING
```

---

# Part 2: Understand ObjectCreated Events

S3 supports several object-created event types.

For example:

```text
ObjectCreated:Put

ObjectCreated:Post

ObjectCreated:Copy

ObjectCreated:CompleteMultipartUpload
```

Instead of choosing only one subtype, this project will use:

```text
s3:ObjectCreated:*
```

That means:

```text
React to supported object-created events.
```

AWS documents `ObjectCreated` as an event family that can invoke a Lambda function when an object is added to S3.

---

# Part 3: Understand the Event Message

When S3 invokes Lambda, Lambda receives an event containing a:

```text
Records
```

array.

An S3 object-created event contains information such as:

```text
eventSource

eventName

awsRegion

bucket name

object key

object size

ETag
```

AWS documents the S3 event message structure and shows object-created events with bucket and object information under `Records`.

A simplified example looks like:

```json
{
  "Records": [
    {
      "eventSource": "aws:s3",
      "eventName": "ObjectCreated:Put",
      "s3": {
        "bucket": {
          "name": "example-bucket"
        },
        "object": {
          "key": "uploads/example.txt",
          "size": 123
        }
      }
    }
  ]
}
```

```text
Lambda
   |
   | Execution role
   v
IAM
   |
   +----> CloudWatch Logs
   |
   +----> S3 GetObject
```

## Lambda Resource-Based Permission

This answers:

```text
Who can invoke Lambda?
```

For this project:

```text
Amazon S3
```

must be allowed to invoke the function.

Architecture:

```text
Amazon S3
    |
    | lambda:InvokeFunction
    v
Lambda
```

AWS specifically requires an S3 notification configuration plus permission for S3 in the Lambda function's resource-based policy.

These permissions are not interchangeable.

# Part 16: Create the Lambda Function Code

Create:

```text
lambda_function.py
```

Use:

```python
import json
import logging
import os
import urllib.parse

import boto3
from botocore.exceptions import ClientError


logger = logging.getLogger()
logger.setLevel(logging.INFO)

EXPECTED_BUCKET = os.environ["BUCKET_NAME"]

s3 = boto3.client("s3")


def build_response(
    status_code,
    body
):
    return {
        "statusCode": status_code,
        "body": body
    }


def process_record(record):
    """
    Process one Amazon S3 event record.
    """

    event_source = record.get(
        "eventSource"
    )

    event_name = record.get(
        "eventName"
    )

    if event_source != "aws:s3":
        raise ValueError(
            "Unsupported event source."
        )

    s3_data = record.get(
        "s3",
        {}
    )

    bucket = s3_data.get(
        "bucket",
        {}
    ).get(
        "name"
    )

    encoded_key = s3_data.get(
        "object",
        {}
    ).get(
        "key"
    )

    event_size = s3_data.get(
        "object",
        {}
    ).get(
        "size"
    )

    event_etag = s3_data.get(
        "object",
        {}
    ).get(
        "eTag"
    )

    if not bucket:
        raise ValueError(
            "Bucket name is missing."
        )

    if not encoded_key:
        raise ValueError(
            "Object key is missing."
        )

    object_key = (
        urllib.parse.unquote_plus(
            encoded_key
        )
    )

    if bucket != EXPECTED_BUCKET:
        raise ValueError(
            f"Unexpected bucket: {bucket}"
        )

    logger.info(
        "Processing S3 object. "
        "bucket=%s key=%s event=%s",
        bucket,
        object_key,
        event_name
    )

    try:
        metadata = s3.head_object(
            Bucket=bucket,
            Key=object_key
        )

    except ClientError:
        logger.exception(
            "Unable to read object metadata. "
            "bucket=%s key=%s",
            bucket,
            object_key
        )
        raise

    result = {
        "bucket": bucket,
        "key": object_key,
        "eventName": event_name,
        "eventSize": event_size,
        "actualSize": metadata.get(
            "ContentLength"
        ),
        "contentType": metadata.get(
            "ContentType"
        ),
        "etag": metadata.get(
            "ETag",
            ""
        ).replace(
            '"',
            ''
        ),
        "eventETag": event_etag,
        "lastModified": (
            metadata[
                "LastModified"
            ].isoformat()
            if metadata.get(
                "LastModified"
            )
            else None
        ),
        "metadata": metadata.get(
            "Metadata",
            {}
        )
    }

    logger.info(
        "Object processed successfully. "
        "result=%s",
        json.dumps(
            result
        )
    )

    return result


def lambda_handler(
    event,
    context
):
    """
    Process Amazon S3 ObjectCreated events.
    """

    logger.info(
        "Invocation started. "
        "request_id=%s",
        context.aws_request_id
    )

    logger.info(
        "Incoming event=%s",
        json.dumps(event)
    )

    records = event.get(
        "Records"
    )

    if not records:
        logger.warning(
            "No S3 records found."
        )

        return build_response(
            400,
            {
                "error": (
                    "No S3 event records "
                    "were provided."
                )
            }
        )

    processed = []
    failures = []

    for index, record in enumerate(
        records
    ):
        try:
            result = process_record(
                record
            )

            processed.append(
                result
            )

        except Exception as exc:
            logger.exception(
                "Record processing failed. "
                "record_index=%s",
                index
            )

            failures.append(
                {
                    "recordIndex": index,
                    "error": str(exc)
                }
            )

    response = {
        "requestId": (
            context.aws_request_id
        ),
        "recordsReceived": len(
            records
        ),
        "recordsProcessed": len(
            processed
        ),
        "recordsFailed": len(
            failures
        ),
        "processed": processed,
        "failures": failures
    }

    if failures:
        logger.error(
            "Invocation completed "
            "with failures. summary=%s",
            json.dumps(response)
        )

        raise RuntimeError(
            "One or more S3 records "
            "failed processing."
        )

    logger.info(
        "Invocation completed "
        "successfully. summary=%s",
        json.dumps(response)
    )

    return build_response(
        200,
        response
    )
```

AWS currently lists `python3.14` as a supported Lambda runtime, and Lambda Python runtimes include Boto3.

# Part 18: Why We Decode the Object Key

Object keys inside S3 events can be URL encoded.

Suppose your file is:

```text
uploads/my report.txt
```

The event might contain an encoded representation.

Therefore the code uses:

```python
urllib.parse.unquote_plus(
    encoded_key
)
```

before calling S3.

---

# Part 19: Why We Use HeadObject

The S3 event already provides some object information.

But:

```python
s3.head_object(...)
```

lets Lambda ask S3 for the current object metadata.

We use it to inspect:

```text
ContentLength

ContentType

ETag

LastModified

Custom metadata
```

This also proves that:

```text
Lambda → S3
```

IAM permissions are working.

# Troubleshooting 10: Recursive Invocation

Avoid this pattern:

```text
S3 uploads/
    |
    v
Lambda
    |
    v
Writes new file
back into uploads/
    |
    v
S3 event
    |
    v
Lambda
    |
    v
...
```

Our Lambda does not write to the source bucket.

If a future processor writes output files, use:

```text
different bucket
```

or:

```text
different non-triggering prefix
```

to prevent the output from matching the input trigger.

AWS explicitly warns about recursive invocation when a Lambda function writes objects back to the same S3 bucket that invokes it.

# What You Should Understand Before Moving On

Do not finish Project 15 thinking only:

```text
I uploaded a file
and Lambda ran.
```

You should understand the complete event-driven chain.

The workflow begins with persistent object storage:

```text
AMAZON S3
```

A file appears:

```text
uploads/project15-test-file.txt
```

S3 detects:

```text
ObjectCreated
```

The bucket's event notification configuration decides whether that event should be sent to a destination. S3 event notifications are configured on the bucket and identify both event types and notification destinations.

Our filter checks:

```text
Prefix:
uploads/
```

The destination is:

```text
AWS Lambda
```

But notification configuration alone is not enough.

Lambda must also allow:

```text
s3.amazonaws.com
```

to perform:

```text
lambda:InvokeFunction
```

AWS explicitly requires this resource-based permission for S3-to-Lambda notifications.

Then Lambda receives an event resembling:

```text
Records
   |
   v
eventSource
eventName
bucket
object
```

AWS documents the S3 event message structure, including `Records`, the S3 bucket name, object key, size, and event name.

Our function extracts:

```text
Bucket

Object key

Event type

Object size

ETag
```

Then Lambda calls:

```text
HeadObject
```

to inspect the actual object metadata.

For that operation, the Lambda execution role needs:

```text
s3:GetObject
```

The permission direction is:

```text
S3
 |
 | invokes
 v
Lambda
```

while separately:

```text
Lambda
 |
 | reads
 v
S3
```

These are two different security relationships.

Finally:

```text
Lambda
   |
   v
CloudWatch Logs
```

records the processing evidence. Lambda automatically sends function logs to CloudWatch Logs when the execution role provides the necessary logging permissions.

Your complete architecture is:

```text
                   FILE UPLOAD
                        |
                        v
                 +-------------+
                 | AMAZON S3   |
                 |             |
                 | uploads/    |
                 +------+------+
                        |
               ObjectCreated Event
                        |
                        v
               Notification Filter
                 prefix=uploads/
                        |
                        v
                 Lambda Policy
                 Allows S3 Invoke
                        |
                        v
                 +-------------+
                 | AWS LAMBDA  |
                 |             |
                 | Python 3.14 |
                 +------+------+
                        |
                 IAM Execution Role
                        |
                        v
                  s3:GetObject
                        |
                        v
                   HeadObject
                        |
                        v
                 Object Metadata
                        |
                        v
                 CLOUDWATCH LOGS
```

Your troubleshooting model should now be:

```text
FILE UPLOADED?
      |
      v
CORRECT BUCKET?
      |
      v
PREFIX MATCHES?
      |
      v
NOTIFICATION EXISTS?
      |
      v
DESTINATION CORRECT?
      |
      v
S3 CAN INVOKE LAMBDA?
      |
      v
LAMBDA INVOKED?
      |
      v
HANDLER RUNNING?
      |
      v
LAMBDA CAN READ S3?
      |
      v
OBJECT KEY CORRECT?
      |
      v
HEADOBJECT WORKS?
      |
      v
CLOUDWATCH LOGS
```

That is the foundation of an event-driven S3 file-processing pipeline.
