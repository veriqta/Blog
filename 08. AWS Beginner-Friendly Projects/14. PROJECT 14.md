# Project 14: Build a Simple Serverless Database Application

Project 14 brings together two major serverless ideas:

```text
COMPUTE
AWS Lambda

+

PERSISTENT STORAGE
Amazon DynamoDB
```

Lambda will run the application logic.

DynamoDB will store the application's data after each Lambda invocation ends.

AWS provides DynamoDB as a managed NoSQL database, and Boto3 provides Python interfaces for creating, reading, updating, deleting, querying, and scanning DynamoDB data.

The finished architecture will look like this:

```text
                TEST EVENT
                    |
                    v
            +----------------+
            | AWS LAMBDA     |
            |                |
            | Python 3.14    |
            | CRUD Logic     |
            +-------+--------+
                    |
                    |
                    | IAM-authorized
                    | DynamoDB calls
                    |
                    v
            +----------------+
            | AMAZON         |
            | DYNAMODB       |
            |                |
            | Table          |
            |                |
            | Partition Key  |
            | id             |
            +-------+--------+
                    |
                    v
              STORED ITEMS

                    |
                    v

             CLOUDWATCH LOGS
```

The application will support:

```text
CREATE

DELETE

LIST
```

You will also deliberately test:


# Part 1: Understand the DynamoDB Data Model

DynamoDB stores information in:

```text
TABLES
```

A table contains:

```text
ITEMS
```

An item contains:

```text
ATTRIBUTES
```

Example:

```json
{
  "id": "item-001",
  "name": "Ann",
  "message": "My first Project 14 record",
  "status": "active"
}
```

One DynamoDB item does not need to look exactly like every other item, although your application should still enforce whatever schema rules it needs.

# Part 2: Understand the Partition Key

Our table will use:

```text
id
```

as its partition key.

Examples:

```text
id = item-001

id = item-002

id = item-003
```

A DynamoDB table with a simple primary key has one partition key. In DynamoDB API terminology, that partition key uses the `HASH` key type.

Our key structure:

```text
veriqta-project-14-items
        |
        v
Partition Key
        |
        v
       id
        |
        v
      String
```

---

# Part 3: Why the Partition Key Matters

Suppose the table contains:

```json
{
  "id": "item-001",
  "name": "Ann"
}
```

and:

```json
{
  "id": "item-002",
  "name": "VERIQTA"
}
```

To retrieve the first record directly, the application uses:

```text
id = item-001
```

Conceptually:

```text
Lambda
   |
   | GetItem
   |
   | id=item-001
   v
DynamoDB
   |
   v
Exact Item
```

Key design matters because DynamoDB access patterns are built around primary keys and indexes. AWS's own Lambda and DynamoDB CRUD example uses a unique `id` as the table's partition key.

We will therefore use:

# Part 22: Create the Lambda Function

Create:

```text
lambda_function.py
```

Use:

```python
import json
import logging
import os
from datetime import datetime, timezone
from decimal import Decimal

import boto3
from botocore.exceptions import ClientError


logger = logging.getLogger()
logger.setLevel(logging.INFO)

TABLE_NAME = os.environ["TABLE_NAME"]

dynamodb = boto3.resource("dynamodb")
table = dynamodb.Table(TABLE_NAME)


class DecimalEncoder(json.JSONEncoder):
    def default(self, obj):
        if isinstance(obj, Decimal):
            if obj % 1 == 0:
                return int(obj)

            return float(obj)

        return super().default(obj)


def clean_for_json(value):
    return json.loads(
        json.dumps(
            value,
            cls=DecimalEncoder
        )
    )


def make_response(
    status_code,
    body
):
    return {
        "statusCode": status_code,
        "body": clean_for_json(body)
    }


def require_text(
    value,
    field_name,
    maximum_length
):
    value = str(
        value or ""
    ).strip()

    if not value:
        raise ValueError(
            f"{field_name} is required."
        )

    if len(value) > maximum_length:
        raise ValueError(
            f"{field_name} cannot exceed "
            f"{maximum_length} characters."
        )

    return value


def create_item(event):

    item = event.get("item") or {}

    item_id = require_text(
        item.get("id"),
        "id",
        100
    )

    name = require_text(
        item.get("name"),
        "name",
        100
    )

    message = require_text(
        item.get("message"),
        "message",
        500
    )

    status = str(
        item.get(
            "status",
            "active"
        )
    ).strip()

    if not status:
        status = "active"

    now = datetime.now(
        timezone.utc
    ).isoformat()

    record = {
        "id": item_id,
        "name": name,
        "message": message,
        "status": status,
        "createdAt": now,
        "updatedAt": now
    }

    table.put_item(
        Item=record,
        ConditionExpression=(
            "attribute_not_exists(id)"
        )
    )

    logger.info(
        "Item created. id=%s",
        item_id
    )

    return make_response(
        201,
        {
            "message": (
                "Item created successfully."
            ),
            "item": record
        }
    )


def get_item(event):

    item_id = require_text(
        event.get("id"),
        "id",
        100
    )

    result = table.get_item(
        Key={
            "id": item_id
        },
        ConsistentRead=True
    )

    item = result.get("Item")

    if not item:
        return make_response(
            404,
            {
                "error": "Item not found.",
                "id": item_id
            }
        )

    logger.info(
        "Item retrieved. id=%s",
        item_id
    )

    return make_response(
        200,
        {
            "item": item
        }
    )


def update_item(event):

    item_id = require_text(
        event.get("id"),
        "id",
        100
    )

    updates = event.get(
        "updates"
    ) or {}

    allowed = {
        "name",
        "message",
        "status"
    }

    filtered = {
        key: value
        for key, value
        in updates.items()
        if key in allowed
    }

    if not filtered:
        raise ValueError(
            "Provide at least one field "
            "to update: name, message, "
            "or status."
        )

    if "name" in filtered:
        filtered["name"] = require_text(
            filtered["name"],
            "name",
            100
        )

    if "message" in filtered:
        filtered["message"] = require_text(
            filtered["message"],
            "message",
            500
        )

    if "status" in filtered:
        filtered["status"] = require_text(
            filtered["status"],
            "status",
            50
        )

    names = {}
    values = {}
    parts = []

    for index, (
        field,
        value
    ) in enumerate(
        filtered.items()
    ):

        name_token = f"#f{index}"
        value_token = f":v{index}"

        names[name_token] = field
        values[value_token] = value

        parts.append(
            f"{name_token} = {value_token}"
        )

    names["#updated"] = "updatedAt"

    values[":updated"] = datetime.now(
        timezone.utc
    ).isoformat()

    parts.append(
        "#updated = :updated"
    )

    result = table.update_item(
        Key={
            "id": item_id
        },
        UpdateExpression=(
            "SET "
            + ", ".join(parts)
        ),
        ExpressionAttributeNames=names,
        ExpressionAttributeValues=values,
        ConditionExpression=(
            "attribute_exists(id)"
        ),
        ReturnValues="ALL_NEW"
    )

    logger.info(
        "Item updated. id=%s",
        item_id
    )

    return make_response(
        200,
        {
            "message": (
                "Item updated successfully."
            ),
            "item": result["Attributes"]
        }
    )


def delete_item(event):

    item_id = require_text(
        event.get("id"),
        "id",
        100
    )

    result = table.delete_item(
        Key={
            "id": item_id
        },
        ConditionExpression=(
            "attribute_exists(id)"
        ),
        ReturnValues="ALL_OLD"
    )

    logger.info(
        "Item deleted. id=%s",
        item_id
    )

    return make_response(
        200,
        {
            "message": (
                "Item deleted successfully."
            ),
            "item": result.get(
                "Attributes"
            )
        }
    )


def list_items(event):

    requested_limit = event.get(
        "limit",
        25
    )

    try:
        requested_limit = int(
            requested_limit
        )
    except (
        TypeError,
        ValueError
    ):
        raise ValueError(
            "limit must be a number."
        )

    requested_limit = max(
        1,
        min(
            requested_limit,
            100
        )
    )

    scan_arguments = {
        "Limit": requested_limit
    }

    exclusive_start_key = event.get(
        "exclusiveStartKey"
    )

    if exclusive_start_key:
        scan_arguments[
            "ExclusiveStartKey"
        ] = exclusive_start_key

    result = table.scan(
        **scan_arguments
    )

    response = {
        "count": result.get(
            "Count",
            0
        ),
        "items": result.get(
            "Items",
            []
        )
    }

    if result.get(
        "LastEvaluatedKey"
    ):
        response[
            "lastEvaluatedKey"
        ] = result[
            "LastEvaluatedKey"
        ]

    logger.info(
        "Items listed. count=%s",
        response["count"]
    )

    return make_response(
        200,
        response
    )


def lambda_handler(
    event,
    context
):

    logger.info(
        "Invocation started. "
        "request_id=%s",
        context.aws_request_id
    )

    logger.info(
        "Incoming event=%s",
        json.dumps(event)
    )

    action = str(
        event.get(
            "action",
            ""
        )
    ).strip().lower()

    try:

        if action == "create":
            return create_item(event)

        if action == "get":
            return get_item(event)

        if action == "update":
            return update_item(event)

        if action == "delete":
            return delete_item(event)

        if action == "list":
            return list_items(event)

        return make_response(
            400,
            {
                "error": (
                    "Unsupported action."
                ),
                "supportedActions": [
                    "create",
                    "get",
                    "update",
                    "delete",
                    "list"
                ]
            }
        )

    except ValueError as exc:

        logger.warning(
            "Validation error. error=%s",
            str(exc)
        )

        return make_response(
            400,
            {
                "error": str(exc)
            }
        )

    except (
        table.meta.client.exceptions
        .ConditionalCheckFailedException
    ):

        logger.warning(
            "Conditional operation failed."
        )

        return make_response(
            409,
            {
                "error": (
                    "The operation conflicts "
                    "with the current item "
                    "state."
                )
            }
        )

    except ClientError:

        logger.exception(
            "DynamoDB client error."
        )

        return make_response(
            500,
            {
                "error": (
                    "Database operation failed."
                ),
                "requestId": (
                    context.aws_request_id
                )
            }
        )

    except Exception:

        logger.exception(
            "Unhandled application error."
        )

        return make_response(
            500,
            {
                "error": (
                    "Internal application "
                    "error."
                ),
                "requestId": (
                    context.aws_request_id
                )
            }
        )
```

Boto3's higher-level DynamoDB resource interface exposes table objects and common data-plane operations, which is why this function can use methods such as `put_item`, `get_item`, `update_item`, `delete_item`, and `scan`.

# Part 24: Understand CREATE

CREATE performs:

```python
table.put_item(...)
```

with:

```text
attribute_not_exists(id)
```

This prevents a duplicate ID from silently replacing an existing item.

That matters because a normal unconditional `PutItem` can replace the existing item when the same primary key already exists. DynamoDB documentation recommends conditions when you want to prevent that replacement behavior.

# Part 28: Understand LIST and Pagination

A DynamoDB `Scan` can return a `LastEvaluatedKey` when more data remains. Pagination is therefore important once your dataset exceeds a single response.

Our function accepts:

```json
{
  "action": "list",
  "limit": 25
}
```

The response may contain:

```json
{
  "lastEvaluatedKey": {
    "id": "item-025"
  }
}
```

The next request can send that key back:

```json
{
  "action": "list",
  "limit": 25,
  "exclusiveStartKey": {
    "id": "item-025"
  }
}
```

For this beginner lab, the dataset will remain very small, but it is useful to understand that real DynamoDB scans can be paginated.

# Part 58: Understand Why Scan Is Different

A key lookup says:

```text
Find item-001.
```

A scan says:

```text
Read through table items.
```

Those are different workloads.

For a tiny project:

```text
Scan
```

is convenient.

For large production workloads, design your keys and indexes around the application's real access patterns rather than depending heavily on full-table scans.

# What You Should Understand Before Moving On

Do not finish Project 14 thinking only:

```text
I created a DynamoDB table.
```

The important architecture is:

```text
APPLICATION LOGIC
       |
       v
AWS LAMBDA
       |
       v
EXECUTION ROLE
       |
       v
DYNAMODB
```

Lambda is responsible for:

```text
Validation

Application logic

CRUD decisions

Error handling

Logging
```

IAM controls:

```text
What Lambda is allowed to do.
```

DynamoDB handles:

```text
Persistent data.
```

The DynamoDB table uses:

```text
id
```

as the partition key.

That key determines how the application identifies individual records.

AWS's official serverless CRUD example likewise uses a unique `id` partition key before connecting Lambda to the database.

The complete CREATE path is:

```text
CREATE EVENT
     |
     v
LAMBDA
     |
     v
VALIDATE INPUT
     |
     v
IAM CHECK
     |
     v
PutItem
     |
     v
DYNAMODB
     |
     v
ITEM STORED
```

READ becomes:

```text
GET EVENT
   |
   v
LAMBDA
   |
   v
GetItem
   |
   v
Partition key:
id=item-001
   |
   v
DynamoDB
   |
   v
ITEM RETURNED
```

UPDATE becomes:

```text
UPDATE EVENT
     |
     v
Lambda
     |
     v
UpdateItem
     |
     v
Existing DynamoDB Item
     |
     v
New Attribute Values
```

DELETE becomes:

```text
DELETE EVENT
     |
     v
Lambda
     |
     v
DeleteItem
     |
     v
Item Removed
```

And persistence means:

```text
Lambda finishes
     |
     v
Execution environment
may disappear

BUT

DynamoDB item
still exists
```

That is one of the most important architectural lessons in serverless applications.

Your compute layer can be temporary.

Your database layer preserves the application's state.

You also learned to troubleshoot the architecture by identifying the failed layer:

```text
EVENT VALID?
     |
     v
LAMBDA INVOKED?
     |
     v
CODE RUNNING?
     |
     v
TABLE_NAME CORRECT?
     |
     v
IAM AUTHORIZED?
     |
     v
TABLE EXISTS?
     |
     v
KEY CORRECT?
     |
     v
DYNAMODB OPERATION?
     |
     v
CLOUDWATCH LOGS
```

That is much more useful than simply recreating the function whenever something fails.

Project 14 therefore gives you a complete beginner serverless database foundation:

```text
AWS LAMBDA
+
IAM
+
DYNAMODB
+
CLOUDWATCH
```

The next architectural step would be putting an HTTP layer such as API Gateway in front of this backend so external applications can perform these CRUD operations through real HTTP endpoints. AWS's own CRUD tutorial follows that architecture with API Gateway, Lambda, and DynamoDB.
