# Project 6: Create a Simple Database with Amazon RDS

In the previous projects, you built the network and deployed compute into it.

Now you are going to add a database.

But the database will not be placed directly on the public internet.

Instead, you will build this architecture:

```text
                         YOUR COMPUTER
                              |
                           SSH :22
                              |
                              v
                         INTERNET
                              |
                              v
                     INTERNET GATEWAY
                              |
                              v
+----------------------------------------------------------------+
|                 CUSTOM VPC 10.0.0.0/16                         |
|                                                                |
|  PUBLIC SUBNET                                                 |
|  10.0.1.0/24                                                   |
|                                                                |
|  +----------------------+                                      |
|  | EC2 DATABASE CLIENT  |                                      |
|  | Amazon Linux 2023    |                                      |
|  |                      |                                      |
|  | SG: client-sg        |                                      |
|  +----------+-----------+                                      |
|             |                                                  |
|             | MySQL TCP/3306                                   |
|             v                                                  |
|     +------------------------------------------------+         |
|     | RDS SECURITY GROUP                             |         |
|     |                                                |         |
|     | Allow TCP/3306                                 |         |
|     | Source: client-sg                              |         |
|     +----------------------+-------------------------+         |
|                            |                                   |
|                            v                                   |
|                  AMAZON RDS FOR MYSQL                          |
|                  Public access: NO                             |
|                                                                |
|       DB SUBNET GROUP                                          |
|                                                                |
|       PRIVATE SUBNET A              PRIVATE SUBNET B            |
|       10.0.2.0/24                  10.0.3.0/24                  |
|       Availability Zone A          Availability Zone B          |
|                                                                |
+----------------------------------------------------------------+
```

This is a much better starting architecture than placing the database directly on the internet.

AWS recommends private RDS connectivity for common EC2-to-RDS designs. RDS security groups can then allow database connections from specific EC2 security groups rather than from the entire internet.

# Part 1: Understand What Amazon RDS Does

Amazon Relational Database Service is a managed relational database service.

Instead of manually installing MySQL on EC2 and managing everything yourself, RDS handles much of the underlying database infrastructure management.

The database still has:

```text
Database engine
Database users
Passwords
Databases
Tables
Indexes
Connections
SQL
```

But AWS manages much of the infrastructure underneath the database service.

For this lab we will use:

```text
MySQL
```

---

# Part 2: Understand Why the Database Will Be Private

A database server normally does not need random users on the internet connecting directly to its database port.

Our intended path is:

```text
Internet
   |
   X
   |
RDS TCP/3306
```

but:

```text
EC2 application/client
        |
        | TCP/3306
        v
       RDS
```

is allowed.

AWS supports public RDS instances, but a private DB instance is generally more appropriate when the applications connecting to it are already inside the VPC.

# Part 3: Understand the DB Subnet Group

RDS uses a:

```text
DB subnet group
```

to determine which VPC subnets are available for the database deployment.

A DB subnet group must contain subnets in at least two Availability Zones.

Project 4 gave us:

```text
Private subnet:
10.0.2.0/24
```

but only one private subnet.

Therefore we need another private subnet.

We will create:

```text
10.0.3.0/24
```

in another Availability Zone.

Our private database network will become:

```text
VPC
10.0.0.0/16

├── Public subnet
│   10.0.1.0/24
│
├── Private subnet A
│   10.0.2.0/24
│   AZ A
│
└── Private subnet B
    10.0.3.0/24
    AZ B
```

# Part 13: Understand What the Security Group Reference Means

This rule:

```text
3306 from client-sg
```

does not mean:

```text
Allow one fixed EC2 IP address
```

It means that qualifying traffic from resources associated with the referenced security group can be permitted by the RDS security group rule.

That is useful because your application server's private IP might change over time.

You manage the relationship using security groups rather than continuously editing IP addresses.

# Part 50: Troubleshooting Framework

When database connectivity fails, investigate in this order:

```text
1. Is the RDS DB instance available?

2. Am I using the correct endpoint?

3. Am I using the correct port?

4. Does DNS resolve the endpoint?

5. Are EC2 and RDS inside the intended VPC?

6. Does the RDS subnet group contain valid private subnets?

7. Does VPC local routing exist?

8. Does the RDS security group allow TCP/3306?

9. Is the source the correct EC2/client security group?

10. Does the EC2 instance actually use that client security group?

11. Are NACLs blocking traffic?

12. Does TCP/3306 connect?

13. Am I using the correct database username?

14. Is the password correct?

15. Does the requested database exist?
```

Do not immediately make the RDS instance public to solve a connection problem.

Find the actual broken layer.

MySQL normally uses:

```text
3306
```

Our security group uses:

```text
TCP/3306
```

Our client command uses:

```text
-P 3306
```

Those values must agree.

# Troubleshooting 4: Wrong Security Group Source

The RDS inbound rule should not use your EC2 instance ID.

It should use:

```text
veriqta-project-06-client-sg
```

as the security-group source.

The EC2 client itself must actually be associated with that security group.

Check:

```text
EC2
→ Instance
→ Security
```

# Troubleshooting 5: Security Group Uses Your Laptop IP Instead

This might look like:

```text
3306
Source:
YOUR_HOME_IP/32
```

That is not the architecture we are building.

Our database is private.

The intended source is:

```text
CLIENT SECURITY GROUP
```

not:

```text
Internet client IP
```

# Part 67: Create the RDS Database Using CLI

For the CLI example, avoid typing the database password literally into your shell command history.

Read it silently:

```bash
read -s DB_PASSWORD
```

Press Enter after typing it.

Then create the DB instance:

```bash
aws rds create-db-instance \
  --db-instance-identifier veriqta-project-06-mysql \
  --db-instance-class db.t3.micro \
  --engine mysql \
  --allocated-storage 20 \
  --master-username adminuser \
  --master-user-password "$DB_PASSWORD" \
  --db-name veriqtadb \
  --port 3306 \
  --vpc-security-group-ids "$RDS_SG_ID" \
  --db-subnet-group-name veriqta-project-06-db-subnet-group \
  --no-publicly-accessible \
  --no-multi-az \
  --region "$REGION"
```

Available DB classes vary by Region, account, engine version, and current AWS offerings. If `db.t3.micro` is not offered for your chosen configuration, select an appropriate small supported class from the current console or RDS API.

Clear the shell variable when you no longer need it:

```bash
unset DB_PASSWORD
```

# Cleanup Step 1: Decide Whether You Need a Final Snapshot

Before deleting a real production database, think very carefully before skipping a final snapshot.

For this disposable lab, the data is intentionally temporary.

If you do not need the sample table, you can skip the final snapshot.

AWS supports either creating a final DB snapshot or explicitly skipping it when deleting an RDS DB instance.

# What You Should Understand Before Moving On

Do not finish this project thinking only:

```text
I created an RDS database.
```

You should understand why the database connection worked.

RDS was deployed using a DB subnet group containing private subnets across at least two Availability Zones. AWS requires that AZ coverage for an RDS DB subnet group.

The database was configured:

```text
Publicly accessible:
No
```

so the design did not depend on exposing MySQL directly to the internet.

Your EC2 database client lived inside the same VPC.

The VPC's:

```text
10.0.0.0/16 → local
```

routing provided a network path between the EC2 and RDS private addresses.

The RDS security group allowed:

```text
TCP 3306
```

only when the traffic originated from the EC2 client's security-group relationship. AWS documents this security-group-to-security-group model specifically for EC2-to-RDS connectivity.

The MySQL client then connected using:

```text
RDS endpoint
+
Port 3306
+
Database username
+
Database password
```

and you proved the database worked by creating, inserting, querying, updating, and deleting data.

Most importantly, you deliberately removed the database security-group rule and observed that connectivity failed.

That teaches the real lesson:

```text
A database endpoint is not enough.

A route is not enough.

A security group is not enough.

A username is not enough.

A password is not enough.

All required layers must work together.
```

Your complete successful request path was:

```text
EC2 application/client
        |
        | DNS lookup
        v
RDS endpoint
        |
        | TCP/3306
        v
VPC local routing
        |
        v
RDS security group
        |
        | Source = client security group
        v
MySQL
        |
        v
Authentication
        |
        v
Database
        |
        v
Table and data
```

That is a much stronger understanding of RDS than simply knowing where the Create database button is.
