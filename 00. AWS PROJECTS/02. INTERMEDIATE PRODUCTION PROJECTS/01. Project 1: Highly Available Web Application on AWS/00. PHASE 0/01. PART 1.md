# Introduction

Welcome to Project 1 of the VERIQTA Production Engineering Series.

In this project, you will design, build, deploy, secure, monitor, and operate a highly available web application on Amazon Web Services (AWS) using modern cloud-native technologies and production engineering practices.

Unlike many tutorials that focus only on deploying AWS services, this project is designed to simulate how real engineering teams build and manage production applications. Every architectural decision is made with reliability, security, scalability, and operational excellence in mind.

By the end of this project, you will have built a production-style application that continues serving users when application containers fail, traffic increases unexpectedly, or an Availability Zone becomes unavailable.

This project is intended for aspiring and practicing Cloud Engineers, DevOps Engineers, Platform Engineers, Site Reliability Engineers (SREs), Infrastructure Engineers, and Software Engineers who want hands-on experience building resilient systems on AWS.

# Project Overview

Throughout this project, you will build a containerized web application that runs on AWS using a modern production architecture.

The application will be deployed on Amazon ECS using AWS Fargate, fronted by an Application Load Balancer and Amazon CloudFront, protected by AWS WAF, and backed by an Amazon RDS PostgreSQL Multi-AZ database.

Infrastructure will be provisioned using Terraform, while deployments will be automated through GitHub Actions using OpenID Connect (OIDC) authentication.

The project focuses on building a system that is:

* Highly available
* Secure by default
* Fault tolerant
* Scalable
* Observable
* Easy to maintain
* Ready for continuous delivery

Rather than simply deploying services, you will learn how production systems are designed, validated, monitored, and recovered when failures occur.

# Final Architecture

The final solution follows a layered production architecture.

Internet users access the application through Amazon CloudFront.

CloudFront forwards requests to AWS WAF for inspection.

Validated requests are sent to an Application Load Balancer.

The Application Load Balancer distributes traffic across multiple Amazon ECS tasks running on AWS Fargate in different Availability Zones.

Application containers communicate securely with an Amazon RDS PostgreSQL Multi-AZ database located inside private database subnets.

Supporting AWS services provide image storage, secrets management, monitoring, logging, notifications, encryption, and infrastructure automation.

The application is deployed into a custom Virtual Private Cloud (VPC) that contains:

* Two public subnets
* Two private application subnets
* Two private database subnets

Production workloads never run directly on the public internet.

Only the Application Load Balancer is publicly accessible.

Application containers and databases remain inside private networks.

This architecture provides redundancy, security, scalability, and operational resilience.

# Request Flow

Every request follows the same path through the AWS infrastructure.

## Step 1

A user opens the application in a web browser.

Example:

```
https://app.example.com
```

---

## Step 2

Amazon Route 53 resolves the domain name and directs the request to Amazon CloudFront.

---

## Step 3

Amazon CloudFront receives the request.

CloudFront provides:

* Global edge locations
* HTTPS termination
* Performance improvements
* Content caching
* Reduced latency

---

## Step 4

CloudFront forwards the request to AWS WAF.

AWS WAF evaluates every request before it reaches the application.

Common protections include:

* SQL Injection detection
* Cross-Site Scripting (XSS) protection
* Bot mitigation
* Rate limiting
* Managed security rules

Malicious requests are blocked before reaching the application.

---

## Step 5

Approved requests are forwarded to the Application Load Balancer.

The Application Load Balancer continuously monitors the health of all application containers.

Only healthy containers receive traffic.

---

## Step 6

The Application Load Balancer forwards the request to one of the healthy ECS tasks running on AWS Fargate.

If one container becomes unhealthy, traffic is automatically redirected to healthy containers.

---

## Step 7

When database access is required, the application securely connects to Amazon RDS PostgreSQL.

The database runs in a Multi-AZ deployment, providing automatic failover if the primary database becomes unavailable.

---

## Step 8

The application generates the response and returns it through the same path:

```
Application

↓

Application Load Balancer

↓

CloudFront

↓

Internet User
```

This layered request flow improves security, scalability, and availability while ensuring users always communicate with the application through controlled entry points.
