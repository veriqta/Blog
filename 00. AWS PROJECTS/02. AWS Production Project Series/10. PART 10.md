## Part 10: Application Load Balancer (ALB) — The Traffic Distributor

The Application Load Balancer is the front door of your application. It receives all incoming traffic, terminates SSL (HTTPS), checks which backend instances are healthy, and routes requests only to healthy targets. If an entire Availability Zone fails, the ALB automatically routes traffic to the surviving zone.

This is a **Layer 7** load balancer — it understands HTTP, HTTPS, WebSocket, and gRPC. It can route based on URL paths, host headers, query strings, and HTTP methods.

---

### Step 1: Create the ALB

```bash
aws elbv2 create-load-balancer \
    --name veriqta-ha-alb \
    --subnets $PUBLIC_SUBNET_1A $PUBLIC_SUBNET_1B \
    --security-groups $ALB_SG_ID \
    --scheme internet-facing \
    --type application \
    --ip-address-type ipv4 \
    --tags Key=Name,Value=veriqta-ha-alb Key=Project,Value=Veriqta-HA-WebApp Key=Tier,Value=LoadBalancer
```

**Flags explained:**
- `--name`: DNS-friendly name (max 32 characters)
- `--subnets`: Must span at least 2 AZs for high availability
- `--security-groups`: The ALB-SG we created (allows 80/443 from internet)
- `--scheme internet-facing`: Accessible from the internet (use `internal` for private ALBs)
- `--type application`: Layer 7 HTTP/HTTPS load balancer
- `--ip-address-type ipv4`: Standard IPv4 (use `dualstack` for IPv6)

**Capture the ALB ARN and DNS name:**
```bash
ALB_ARN=$(aws elbv2 describe-load-balancers \
    --names veriqta-ha-alb \
    --query 'LoadBalancers[0].LoadBalancerArn' \
    --output text)

ALB_DNS=$(aws elbv2 describe-load-balancers \
    --names veriqta-ha-alb \
    --query 'LoadBalancers[0].DNSName' \
    --output text)

ALB_ZONE_ID=$(aws elbv2 describe-load-balancers \
    --names veriqta-ha-alb \
    --query 'LoadBalancers[0].CanonicalHostedZoneId' \
    --output text)

echo "ALB ARN: $ALB_ARN"
echo "ALB DNS: $ALB_DNS"
echo "ALB Zone ID: $ALB_ZONE_ID"
```

**Wait for the ALB to be active:**
```bash
echo "Waiting for ALB to become active..."
aws elbv2 wait load-balancer-available --load-balancer-arns $ALB_ARN
echo "ALB is active!"
```

**Verify:**
```bash
aws elbv2 describe-load-balancers --load-balancer-arns $ALB_ARN \
    --query 'LoadBalancers[*].[LoadBalancerName,DNSName,State.Code,AvailabilityZones[*].ZoneName]'
```

### Step 2: Create the Target Group

The Target Group is where the ALB sends traffic. It contains your EC2 instances and performs health checks to ensure only healthy instances receive traffic.

```bash
aws elbv2 create-target-group \
    --name veriqta-app-tg \
    --protocol HTTP \
    --port 80 \
    --vpc-id $VPC_ID \
    --health-check-protocol HTTP \
    --health-check-path /health \
    --health-check-port traffic-port \
    --healthy-threshold-count 2 \
    --unhealthy-threshold-count 3 \
    --health-check-timeout-seconds 5 \
    --health-check-interval-seconds 30 \
    --success-code-codes 200 \
    --target-type instance \
    --tags Key=Name,Value=veriqta-app-tg Key=Project,Value=Veriqta-HA-WebApp
```

**Health check parameters explained:**

| Parameter | Value | Why |
|-----------|-------|-----|
| `--health-check-path /health` | `/health` | Your app exposes a dedicated health endpoint |
| `--healthy-threshold-count 2` | 2 checks | Instance marked healthy after 2 consecutive successes |
| `--unhealthy-threshold-count 3` | 3 checks | Instance marked unhealthy after 3 consecutive failures |
| `--health-check-timeout-seconds 5` | 5 seconds | If no response in 5s, it's a failure |
| `--health-check-interval-seconds 30` | 30 seconds | Check every 30 seconds |
| `--success-code-codes 200` | HTTP 200 | Only 200 OK counts as healthy |

**Capture the Target Group ARN:**
```bash
TG_ARN=$(aws elbv2 describe-target-groups \
    --names veriqta-app-tg \
    --query 'TargetGroups[0].TargetGroupArn' \
    --output text)

echo "Target Group ARN: $TG_ARN"
```

**Verify:**
```bash
aws elbv2 describe-target-groups --target-group-arns $TG_ARN \
    --query 'TargetGroups[*].[TargetGroupName,Protocol,Port,HealthCheckPath,HealthCheckProtocol]'
```

### Step 3: Create the Listener

The Listener defines what port the ALB listens on and what to do with incoming traffic.

**HTTP Listener (port 80):**
```bash
aws elbv2 create-listener \
    --load-balancer-arn $ALB_ARN \
    --protocol HTTP \
    --port 80 \
    --default-actions Type=forward,TargetGroupArn=$TG_ARN \
    --tags Key=Name,Value=veriqta-http-listener Key=Project,Value=Veriqta-HA-WebApp
```

**Capture the Listener ARN:**
```bash
LISTENER_ARN=$(aws elbv2 describe-listeners \
    --load-balancer-arn $ALB_ARN \
    --query 'Listeners[?Port==`80`].ListenerArn' \
    --output text)

echo "Listener ARN: $LISTENER_ARN"
```

**Verify the listener:**
```bash
aws elbv2 describe-listeners --listener-arns $LISTENER_ARN \
    --query 'Listeners[*].[Protocol,Port,DefaultActions[*].Type,DefaultActions[*].TargetGroupArn]'
```

### Step 4: Test the ALB (It Will Fail — That's Expected)

Right now, the ALB has no registered targets (no EC2 instances). Let's verify it responds correctly:

```bash
curl -I http://$ALB_DNS
```

**Expected response:**
```
HTTP/1.1 503 Service Unavailable
```

**Why 503?** The ALB is working, but there are no healthy targets. This is correct behavior. Once we register instances, you'll get 200 OK.

**Verify the ALB DNS resolves:**
```bash
nslookup $ALB_DNS
```

You should see multiple IP addresses (one per AZ). This is the ALB's multi-AZ nature.

### Step 6: Understanding ALB Pricing

| Component | Cost (us-east-1) |
|-----------|-----------------|
| ALB per hour | $0.0225 (~$16.43/month) |
| LCU (Load Balancer Capacity Unit) per hour | $0.008 |
| Data processed | Included in LCU |

**What is an LCU?**
LCU measures four dimensions:
1. **New connections** (per second)
2. **Active connections** (concurrent)
3. **Processed bytes** (GB per hour)
4. **Rule evaluations** (per second)

You're billed for the highest dimension. For a small application, you'll rarely exceed the minimum 1 LCU.

**Total ALB cost for this project:** ~$16–25/month

### Step 7: ALB Architecture Deep Dive

```
Internet User
      │
      ▼
┌─────────────────┐
│   Route 53      │  (DNS → ALB DNS, Part 41)
│   (Optional)    │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  ALB (Public)   │
│  • SSL Terminate│  (HTTPS → HTTP, Part 45)
│  • Health Check │
│  • Path Route   │
└────────┬────────┘
         │
    ┌────┴────┐
    ▼         ▼
┌───────┐  ┌───────┐
│Target │  │Target │
│  1a   │  │  1b   │
│(EC2)  │  │(EC2)  │
└───────┘  └───────┘
```

**What happens during a failure:**
1. **Instance fails health check** (3 consecutive failures)
2. ALB stops sending traffic to that instance
3. If all instances in AZ-a fail, ALB routes 100% to AZ-b
4. If Auto Scaling replaces the failed instance, ALB resumes traffic after 2 healthy checks
