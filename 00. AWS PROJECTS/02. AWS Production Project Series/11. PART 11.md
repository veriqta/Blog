## Part 11: S3 Bucket for ALB Access Logs — Audit & Compliance Foundation

Every production load balancer must log access for three reasons: **troubleshooting** (why did that request fail?), **security auditing** (who accessed what and when?), and **compliance** (SOC 2, PCI-DSS, HIPAA require access logs).

AWS ALB can deliver logs to S3 automatically. We'll build a properly secured, lifecycle-managed bucket with the exact permissions ALB needs.

---

### Step 1: Create a Unique S3 Bucket Name

S3 bucket names are **globally unique** across all AWS accounts worldwide. Use your account ID or a random suffix.

```bash
# Get your AWS Account ID
ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
echo "Account ID: $ACCOUNT_ID"

# Create a unique bucket name
BUCKET_NAME="veriqta-alb-logs-${ACCOUNT_ID}"
echo "Bucket Name: $BUCKET_NAME"
```

---

### Step 2: Create the S3 Bucket

```bash
aws s3api create-bucket \
    --bucket $BUCKET_NAME \
    --region us-east-1
```

> **Note:** In `us-east-1`, you don't need `--create-bucket-configuration`. In other regions, you'd add: `--create-bucket-configuration LocationConstraint=us-west-2`

**Verify creation:**
```bash
aws s3api head-bucket --bucket $BUCKET_NAME
# No output = success
```

---

### Step 3: Block All Public Access (Security Critical)

S3 buckets are private by default, but explicit blocks prevent accidental public exposure.

```bash
aws s3api put-public-access-block \
    --bucket $BUCKET_NAME \
    --public-access-block-configuration \
        BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true
```

**Verify:**
```bash
aws s3api get-public-access-block --bucket $BUCKET_NAME
```

Expected output:
```json
{
    "PublicAccessBlockConfiguration": {
        "BlockPublicAcls": true,
        "IgnorePublicAcls": true,
        "BlockPublicPolicy": true,
        "RestrictPublicBuckets": true
    }
}
```

---

### Step 4: Enable Server-Side Encryption

Encrypt logs at rest using AWS-managed KMS keys.

```bash
aws s3api put-bucket-encryption \
    --bucket $BUCKET_NAME \
    --server-side-encryption-configuration '{
        "Rules": [
            {
                "ApplyServerSideEncryptionByDefault": {
                    "SSEAlgorithm": "AES256"
                },
                "BucketKeyEnabled": true
            }
        ]
    }'
```

**Why `BucketKeyEnabled: true`?**
- Reduces KMS API call costs by 99%
- Uses a bucket-level key instead of individual object keys
- Required for cost-effective encryption at scale

**Verify:**
```bash
aws s3api get-bucket-encryption --bucket $BUCKET_NAME
```

---

### Step 5: Enable Versioning (Protect Against Accidental Deletion)

```bash
aws s3api put-bucket-versioning \
    --bucket $BUCKET_NAME \
    --versioning-configuration Status=Enabled
```

**Why versioning for logs?**
- Prevents accidental overwrites
- Allows recovery from malicious deletion
- Required for some compliance frameworks

---

### Step 6: Configure Lifecycle Policy (Cost Optimization)

Access logs accumulate fast. A busy ALB can generate gigabytes per day. We'll auto-transition old logs to cheaper storage and eventually delete them.

```bash
cat > lifecycle-policy.json << 'EOF'
{
    "Rules": [
        {
            "ID": "ALB-Logs-Lifecycle",
            "Status": "Enabled",
            "Filter": {
                "Prefix": ""
            },
            "Transitions": [
                {
                    "Days": 30,
                    "StorageClass": "STANDARD_IA"
                },
                {
                    "Days": 90,
                    "StorageClass": "GLACIER"
                }
            ],
            "Expiration": {
                "Days": 365
            },
            "NoncurrentVersionTransitions": [
                {
                    "NoncurrentDays": 30,
                    "StorageClass": "STANDARD_IA"
                },
                {
                    "NoncurrentDays": 90,
                    "StorageClass": "GLACIER"
                }
            ],
            "NoncurrentVersionExpiration": {
                "NoncurrentDays": 365
            }
        }
    ]
}
EOF

aws s3api put-bucket-lifecycle-configuration \
    --bucket $BUCKET_NAME \
    --lifecycle-configuration file://lifecycle-policy.json

rm lifecycle-policy.json
```

**Lifecycle breakdown:**

| Days | Action | Storage Class | Cost Impact |
|------|--------|---------------|-------------|
| 0–30 | Active access | STANDARD | Full price |
| 30–90 | Infrequent access | STANDARD_IA | ~40% cheaper |
| 90–365 | Archive | GLACIER | ~80% cheaper |
| 365+ | Deleted | — | $0 |

**Verify:**
```bash
aws s3api get-bucket-lifecycle-configuration --bucket $BUCKET_NAME
```

### Step 7: Grant ALB Permission to Write Logs

ALB uses a special AWS account to deliver logs. The account ID varies by region. For `us-east-1`, it's `127311923021`.

**Create the bucket policy:**

```bash
cat > bucket-policy.json << EOF
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "ALBAccessLogs",
            "Effect": "Allow",
            "Principal": {
                "AWS": "arn:aws:iam::127311923021:root"
            },
            "Action": "s3:PutObject",
            "Resource": "arn:aws:s3:::${BUCKET_NAME}/veriqta-ha-alb/*"
        }
    ]
}
EOF

aws s3api put-bucket-policy \
    --bucket $BUCKET_NAME \
    --policy file://bucket-policy.json

rm bucket-policy.json
```

**Why `127311923021`?**
This is AWS's ELB service account for `us-east-1`. Each region has a different account ID:

| Region | ELB Account ID |
|--------|---------------|
| us-east-1 | 127311923021 |
| us-east-2 | 033677994240 |
| us-west-1 | 027434742980 |
| us-west-2 | 797873946194 |
| eu-west-1 | 156460612806 |
| eu-central-1 | 054676820928 |

**Verify the policy:**
```bash
aws s3api get-bucket-policy --bucket $BUCKET_NAME --query Policy --output text | python3 -m json.tool
```

### Step 8: Configure ALB to Deliver Access Logs

```bash
aws elbv2 modify-load-balancer-attributes \
    --load-balancer-arn $ALB_ARN \
    --attributes \
        Key=access_logs.s3.enabled,Value=true \
        Key=access_logs.s3.bucket,Value=$BUCKET_NAME \
        Key=access_logs.s3.prefix,Value=veriqta-ha-alb
```

**Verify:**
```bash
aws elbv2 describe-load-balancer-attributes --load-balancer-arn $ALB_ARN \
    --query 'Attributes[?Key==`access_logs.s3.enabled` || Key==`access_logs.s3.bucket` || Key==`access_logs.s3.prefix`]'
```

Expected output:
```json
[
    {"Key": "access_logs.s3.enabled", "Value": "true"},
    {"Key": "access_logs.s3.bucket", "Value": "veriqta-alb-logs-123456789012"},
    {"Key": "access_logs.s3.prefix", "Value": "veriqta-ha-alb"}
}
```

### Step 9: Test Log Delivery

**Generate some traffic:**
```bash
# Make several requests to the ALB
for i in {1..5}; do
    curl -s -o /dev/null -w "%{http_code}\n" http://$ALB_DNS
```

**Wait 5 minutes** (ALB delivers logs every 5 minutes)

**Check for logs:**
```bash
aws s3 ls s3://$BUCKET_NAME/veriqta-ha-alb/ --recursive
```

You should see paths like:
```
veriqta-ha-alb/AWSLogs/123456789012/elasticloadbalancing/us-east-1/2026/07/25/123456789012_elasticloadbalancing_us-east-1_veriqta-ha-alb_20260725T1800Z_1.2.3.4_5abcdef6.log.gz
```

**Download and inspect a log file:**
```bash
# List the most recent log file
LOG_FILE=$(aws s3 ls s3://$BUCKET_NAME/veriqta-ha-alb/ --recursive | tail -1 | awk '{print $4}')

# Download it
aws s3 cp s3://$BUCKET_NAME/$LOG_FILE ./alb-log.gz

# Decompress and view
gunzip -c ./alb-log.gz | head -5

# Clean up
rm ./alb-log.gz
```


### Step 10: Enable S3 Access Logging (Meta-Logging)

Log who accesses your log bucket. This is required for some compliance frameworks.

```bash
# Create a logs-for-logs bucket (or use the same bucket with a different prefix)
META_LOG_BUCKET="${BUCKET_NAME}-meta"

aws s3api create-bucket --bucket $META_LOG_BUCKET --region us-east-1

aws s3api put-public-access-block \
    --bucket $META_LOG_BUCKET \
    --public-access-block-configuration \
        BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true

# Enable access logging on the main bucket
aws s3api put-bucket-logging \
    --bucket $BUCKET_NAME \
    --bucket-logging-status '{
        "LoggingEnabled": {
            "TargetBucket": "'$META_LOG_BUCKET'",
            "TargetPrefix": "s3-access-logs/"
        }
    }'
```

> **Note:** For learning, this is optional. In production, meta-logging is often required.
